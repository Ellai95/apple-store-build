# Индивидуальные ключи AppStore+

Код платного доступа подготовлен, но живой сервис, подпись и iPhone ещё не проверены. Публичный переход до этой проверки не запускается.

## Два независимых этапа

1. Клиент присылает P12 и mobileprovision. Бот делает персональную установку и подключает сертификат. Это не выдаёт платную лицензию.
2. Владелец после оплаты создаёт индивидуальный ключ. Клиент вводит его в AppStore+. Срок начинается при погашении ключа.

APPSTORE_PAID_ACCESS=1 включён по умолчанию в настроенном Python-сервисе. Значение 0 оставляет прежний пилотный протокол только для отдельного тестового окружения. В базовой IPA платной версии обязательно AppStoreRequiresLicense=true: сервер доставки отклоняет старый пакет без этого флага.

Платная IPA без персонального StoreActivation.json открывает только экран активации. Сохранённой сессии недостаточно: на старте требуется серверная проверка. Подтверждение действует не более 120 секунд и ограничено реальным окончанием лицензии и сертификата. Проверка повторяется раз в минуту в активном приложении. При уходе в фон доступ перепроверяется. Отсчёт подтверждения использует монотонное время, а не только календарные часы телефона.

## Команды владельца

В том же окружении с постоянным APPSTORE_MASTER_KEY и APPSTORE_DB:

```bash
python3 licenses.py plans
python3 licenses.py accounts
python3 licenses.py issue --account ACCOUNT_ID --plan customer_3m
```

Последняя команда выводит единственный новый ключ. Его владелец передаёт покупателю вручную. Сервис хранит хеш; ключа нет в установочной ссылке. Доступного клиентам HTTP-метода выдачи ключей нет. По истории покупки сертификата владелец выбирает подходящий customer_* или external_* тариф; само приложение не назначает скидку.

| План | Срок | Цена |
|---|---|---:|
| external_6m | 6 месяцев | 1000 ₽ |
| external_12m | 1 год | 2000 ₽ |
| external_lifetime | Навсегда | 3500 ₽ |
| customer_1m | 1 месяц | 300 ₽ |
| customer_3m | 3 месяца | 500 ₽ |
| customer_6m | 6 месяцев | 800 ₽ |
| customer_12m | 1 год | 1000 ₽ |

Сроки календарные, с корректной обработкой конца месяца и високосного года. Новый ключ добавляет срок к текущему окончанию активной лицензии; просроченной — от момента ввода. Повтор уже погашенного ключа ничего не продлевает. Ключ связан с аккаунтом Telegram и устройством, выбранными при персональной выдаче. Новый сертификат для того же аккаунта/устройства не теряет лицензию. Навсегда — отдельный признак, не фиктивная дата.

Отозвать ещё не выданный/утёкший ключ через приватный файл:

```bash
python3 licenses.py revoke-key --key-file /private/key.txt
python3 licenses.py revoke-license --account ACCOUNT_ID
python3 licenses.py restore-license --account ACCOUNT_ID
```

Отзыв ключа не отменяет ранее купленное время: для блокировки уже активного доступа используется revoke-license. Восстановление выполняет владелец отдельно; новый ключ не обходит приостановленную лицензию.

## Что проверить перед выдачей клиентам

1. Новая платная IPA из Actions с обязательной активацией; первая тестовая IPA 5.0 без этого экрана не подходит.
2. `python3 check_setup.py`: настройки тестового бота, мастер-ключ, подготовленная основа IPA, zsign, OpenSSL, HTTPS.
3. Получение двух файлов, реальная подпись и установка по ссылке, автоматический импорт сертификата без ручного ввода файлов в AppStore+.
4. Без оплаченного ключа каталог закрыт; после ввода открывается; чужой ключ отклоняется.
5. Истечение тестового короткого срока, новый ключ, повтор ключа, перезапуск приложения и временная недоступность сервиса.
6. Переустановка, замена сертификата, сохранение бессрочной лицензии и персональной конфигурации при обновлении.

45 локальных Python-тестов проходят. Проверены в том числе HTTP POST с настоящей P-256 подписью, подмена тела запроса, повтор запросов, конкурентное погашение, календарные периоды, замена сертификата и доступность установки до оплаты. В тесте подписи самой IPA используется макет signer. Проверка монотонного срока на Swift добавлена в следующий macOS-запуск, здесь она не исполнялась.

Для публичной работы сервер проверки ключей должен быть постоянно доступен. Если он запущен только на домашнем ПК, выключение ПК не позволит клиенту пройти новую проверку доступа. На этом этапе постоянный хостинг не настроен. Лицензия не заменяет действительный сертификат и не гарантирует работу приложения после его отзыва.
