# AppStore+ — бот выдачи персонального установщика

Подготовлен код тестового бота. Он ещё не запущен и не проверен на iPhone. Существующий @appleipastore_bot не изменён.

## Что отправляет владелец

В отдельный тестовый бот отправляются два документа: .p12 и .mobileprovision — вместе одним отправлением или отдельно, в любом порядке. Пароль по умолчанию — 1, вводить его не требуется. Для другого пароля сначала отправить /password ПАРОЛЬ, затем файлы. Если пароль 1 не подошёл, бот не выдаёт ссылку: можно указать правильный пароль и повторить. Если профиль выпущен на один UDID, бот определяет его самостоятельно. Для многопользовательского профиля используется /udid UDID. Как только комплект заполнен, автоматически начинается подготовка.

Другой вариант — /udid UDID без файлов. При настроенном ONE_IBOT_API_KEY бот запрашивает уже выпущленный сертификат через GET /certificate и запускает тот же процесс. Он не покупает сертификат, не регистрирует новый UDID и не использует Telegram api_id/api_hash для доступа к провайдеру.

## Что делает бот

1. Принимает сообщения только в личном чате от разрешённых numeric Telegram IDs.
2. Сохраняет черновик сертификата и пароля в зашифрованной SQLite. Черновики истекают через час; /cancel удаляет их сразу. Исходные сообщения в Telegram автоматически не удаляются.
3. Проверяет P12, пароль, соответствие профиля, наличие нужного UDID и срок действия.
4. Добавляет в готовую unsigned IPA AppStore+ персональный StoreActivation.json. В нём нет P12 или ключа провайдера.
5. Вызывает локальный zsign и проверяет структуру результата: идентификатор магазина, наличие профиля и ресурсов подписи, сохранение bootstrap. Это не независимая криптографическая проверка подписи iOS.
6. Размещает только персональную IPA, manifest и страницу установки в закрытой выдаче с непредсказуемой ссылкой. Ключи и профиль отдельно не публикуются.
7. Отправляет кнопку «Установить AppStore+» и дату окончания доступа. /install повторно показывает последнюю готовую ссылку, в том числе если отправка сообщения прервалась.
8. После установки магазин обращается к сервису активации и автоматически подключает сертификат. Ручного импорта в основном сценарии нет.

Задачи обрабатываются по одной в отдельном worker, polling бота продолжается. При сбое подписи ссылка не выдаётся, созданная активация отключается. /sign позволяет повторить с сохранённым черновиком. Промежуточные файлы удаляются после завершения процесса; аварийное завершение ОС может оставить .job-* каталоги, которые администратору нужно очистить после остановки процесса. Полноценная долговечная очередь и гарантированная обработка ровно один раз при аварии пока не реализованы.

Персональные ссылки истекают не позже семи дней, срок доступа ограничен сроком сертификата. Истёкшие файлы очищаются работающим ботом; доступ к истёкшим/отключённым ссылкам блокируется HTTP-сервисом. До тестирования запуск ограничен явно указанными IDs, не открывать бота публично.

## Что нужно для запуска

- Отдельный тестовый бот BotFather и его токен. Не запускать bot.py и delivery_bot.py на одном токене одновременно; не использовать текущий бот Mini App для пилота.
- Linux/WSL или другая проверенная среда с Python 3.11+, OpenSSL и рабочим zsign. Прямой запуск всех компонентов на Windows здесь не проверен.
- Готовая unsigned IPA AppStore+ с bundle ID ru.ipa95.applestore. Перед персонализацией исходный пакет не должен содержать _CodeSignature. Пересборка магазина для каждого клиента не нужна.
- Работающий HTTPS origin и reverse proxy к сервису на 127.0.0.1:8787. Он обслуживает /v1/* и /delivery/*. Сертификат HTTPS должен доверяться iPhone. Закрытая выдача здесь означает непредсказуемую персональную ссылку, а не дополнительный логин: любой владелец ссылки может скачать IPA, поэтому не публиковать её.
- Постоянный APPSTORE_MASTER_KEY: случайные 32 байта в base64, отдельный от исходников. Не менять после создания базы.

Переменные среды:

```text
APPSTORE_BOT_TOKEN=<локальный токен тестового бота>
APPSTORE_MASTER_KEY=<32 random bytes, base64>
APPSTORE_DB=/private/appstore/store.sqlite3
APPSTORE_UNSIGNED_IPA=/private/appstore/AppStore-Plus-unsigned.ipa
APPSTORE_ORIGIN=https://your-domain.example
APPSTORE_DELIVERY_ROOT=/private/appstore/delivery
APPSTORE_ZSIGN=/usr/local/bin/zsign
APPSTORE_DELIVERY_ALLOWED_IDS=<ваш numeric Telegram ID>
APPSTORE_ACCESS_DAYS=30
APPSTORE_SUPPORT_URL=https://t.me/your_support
ONE_IBOT_API_KEY=<необязательно: отдельный ключ API выдачи сертификатов>
```

На первом пилоте APPSTORE_ACCESS_DAYS задаёт длительность доступа; автоматический выбор тарифа, платежи и подключение действующих клиентов ещё не реализованы. Если сертификат заканчивается раньше, доступ будет ограничен его сроком.

Установка зависимостей: python3 -m pip install -r requirements.txt.
В двух процессах с одинаковой конфигурацией:

```bash
python3 service.py serve
python3 delivery_bot.py
```

API бота уже поддерживает отправку файлов через Telegram Bot API, не требует Telethon или пользовательской Telegram-сессии. Учитывать, что секреты, отправленные в обычный чат бота, проходят через Telegram.

Общие IPA каталога пользователь решил хранить в GitHub Releases. Персональная IPA с кодом активации не размещается в публичных релизах. GitHub Actions для обработки каждой выдачи не нужен; подпись выполняется на машине, где работает бот. Выключенный ПК означает недоступность бота и активации.

## Проверки и ограничения

35 локальных тестов проходят. Проверены оба порядка получения файлов, два документа с общим media_group_id, автоматический пароль 1 и сохранение явно заданного другого пароля. Среди них: настоящий тестовый P12/CMS, отклонение чужого UDID, изоляция отправителей, автоматический переход от двух файлов и пароля к задаче, получение пары по UDID, обработка сбоя signer, закрытая выдача, HTTP Range/HEAD и истечение ссылок.

В тестах доставки вызов zsign заменён структурным макетом: это не настоящая подпись Mach-O. Настоящий zsign в этой среде отсутствует. Живой Telegram Bot API, API One_iBot и установка на iPhone не проверены. До пилота нужны действительная пара владельца и настоящая подпись реальной IPA.

Серверная подпись произвольных приложений из каталога этим ботом не добавлена: бот подписывает именно установщик AppStore+. Основной магазин пока использует локальный движок подписи.

Тесты: python3 -m unittest discover -s tests -v.

При получении сертификата по UDID используется p12_password из ответа провайдера; если поле отсутствует, тестовый бот пробует 1. В любом случае пара проходит криптографическую проверку пароля до подписи. При загрузке документов по умолчанию применяется 1, даже если этот пароль не подходит конкретному P12; это вызывает отказ, а не обход пароля.


## Подготовка IPA из Actions

Тестовая IPA из Actions содержит ad-hoc подпись. Перед использованием как основы бота выполните один раз:

```bash
python3 prepare_base.py "/path/AppStore+.ipa" "/private/appstore/AppStore-Plus-unsigned.ipa"
```

Скрипт принимает только наш bundle ID, сохраняет ресурсы и права исполняемых файлов, удаляет прежние ресурсы подписи и профили. Он отклоняет персонализированные пакеты и встроенные P12. После персонализации zsign заново подписывает пакет действительным сертификатом. Подготовленный файл сам по себе не предназначен для установки.

На реальной IPA 5.0 (492) проверены подготовка основы и добавление тестового bootstrap. Это не проверка реальной подписи или Telegram: для живого пилота всё ещё нужны настроенный тестовый бот, HTTPS origin и рабочий zsign.

Перед запуском выполните `python3 check_setup.py`. Проверка не обращается к Telegram и не выводит значения секретов. Она проверяет наличие настроек, подготовленной основы, OpenSSL и исполняемого zsign.
