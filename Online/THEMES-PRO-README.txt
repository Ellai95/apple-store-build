Apple Store 4.9 · Pro

Оплата и выдача
Клиент: Pro → «Активировать Pro» → копирует персональный код → «Оплатить 300 ₽» → карта или СБП → «Я оплатил» → отправка чека и кода в Telegram либо WhatsApp.
Разработчик проверяет чек. Activate-Pro.cmd просит только персональный код и выдаёт 365 дней. Пользователь обновляет доступ; вводить отдельный код не нужно. Оплата автоматически не проверяется.
Grant-Pro.cmd и старое имя Create-Pro-Code.cmd работают как Activate-Pro.cmd, без генерации секрета.
Revoke-Pro.cmd удаляет доступ только указанному устройству. Disable-Pro.cmd отключает Pro глобально без удаления приложений и сертификатов.
Новая выдача заменяет срок, а не складывает дни. Старые доступы 4.7 сохраняются и действуют по тому же персональному коду.
В локальном pro-work сохраняются отчёт выдачи и резервные копии. Не загружайте эту папку на GitHub.

Сеть и прогресс
Обычные .cmd используют прямой доступ к R2/GitHub. При DNS/соединении включите Happ с SOCKS 10808 и используйте варианты -Happ.cmd.
Окно сначала запрашивает персональный код, затем показывает этапы чтения, проверки, публикации и подтверждения. Нет молчаливого ожидания до ввода кода. При таймауте команда завершится с ошибкой; её можно повторить.

Возможности Pro
— Aurora, Black Gold, Ocean, Liquid Glass: стеклянные материалы, медленное смешивание цветов, белое/чёрное оформление.
— Свои обои: фото только на iPhone, размытие, затемнение, плотность карточек и акценты.
— До пяти параллельных загрузок IPA. Подпись, локальный сервер и системные подтверждения последовательны.
— Запрос обновления любого приложения и доступ к подготовленным ранним версиям.
— Запрос индивидуальной функции/идеи через Telegram или WhatsApp с персональным кодом.
— Без рекламных окон.
Обычная установка, импорт сертификата и Bundle ID остаются бесплатными.

Очередь
Оставляйте приложение открытым до передачи IPA iOS. Загрузки обычной сессии не обещают непрерывную работу в фоне.
При ошибке подписи очередь приостанавливается: исправьте причину и нажмите «Продолжить очередь». Загрузки можно отменять отдельно. Подписываемый/передаваемый файл не удаляется из очереди кнопкой отмены.
Следующая установка начинается только после полной передачи предыдущего IPA. «Передано iOS» не является подтверждением успешной установки системой.
После перезапуска незавершённые временные файлы очереди удаляются; загрузку запускают снова. Для пяти больших IPA требуется достаточно свободного места.
Liquid Glass останавливает движение при неактивном приложении/уменьшении движения/низком энергопотреблении; при уменьшении прозрачности используются читаемые обычные поверхности.

Ранние версии
Add-Early-Release.cmd → путь к IPA → название → версия → ID карточки (например whatsapp; можно Enter) → персональный код клиента либо Enter для всех Pro.
Файл проверяется и загружается в Ellai95/apple-ipa-files, релиз ipa-archive-1. Затем только personalization.extras.earlyReleases получает запись. Общий catalog.json, конфигурация обновления Apple Store и обычная карточка приложения не меняются.
Готовые записи доступны в приложении: Pro → Ранние обновления. По умолчанию запись действует 30 дней; это срок видимости ранней версии, а не срок сертификата или Pro.
Никакой ранний IPA в комплект не выдуман и не загружен. Запрос клиента не создаёт обновление автоматически: разработчик должен его подготовить.
Для редактирования/удаления записи: Get-Themes.cmd → Personalization.json → extras.earlyReleases → Publish-Themes.cmd.
Пустой allowedCodes означает все Pro; список кодов — только указанную аудиторию. Это контроль видимости в обычном клиенте; публичная ссылка GitHub не защищает файл от пересылки. Для закрытого скачивания нужен сервер.

Индивидуальные функции
extras.deviceOverrides: [{"code":"ПЕРСОНАЛЬНЫЙ_КОД_32_СИМВОЛА","flags":{"glassTheme":true}}].
Доступные переключатели: earlyAccess, parallelDownloads, glassTheme, featureRequests. Индивидуальное значение имеет приоритет над общим. Pro должен быть активен.
Новый программный механизм сначала разрабатывается и включается в IPA; после обновления уже встроенную функцию можно включать одному профилю онлайн. Запрос идеи не гарантирует мгновенную реализацию.
Перед изменениями скачивайте текущий Personalization.json через Get-Themes.cmd, чтобы не потерять новые ранние версии/профили. При публикации текущие grants сохраняются.

Онлайн-реквизиты и темы
Personalization.json содержит payment, paymentDetails, offers, themes, extras. Цены/карта/СБП/получатель/ссылки и изображения меняются онлайн через Publish-Themes.cmd.
Поле activationHash сохранено только для совместимости чтения конфигурации старым 4.7. Новая 4.9 проверяет код устройства, срок и разрешённые функции без ввода секрета.
Публикация защищена повторным чтением текущей конфигурации и резервной копией. Каталог и IPA не очищаются. Одновременно запускать разные команды публикации не рекомендуется.
Доступ проверяется клиентом и может быть обойдён в изменённом IPA. Реестр содержит случайные идентификаторы/сроки. Онлайн-отзыв применяется после получения новой конфигурации.
