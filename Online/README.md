# Тест обновления 4.1 → 4.2

Для этого выпуска запускайте `Publish-Test-Update.cmd` после сборки GitHub.
IPA и release.json берутся из одного артефакта Apple-Store-4.2-IPA.
Не подписывайте эту IPA ботом перед публикацией.

Скрипт берёт текущую онлайн-конфигурацию (при её отсутствии — комплектную),
сохраняет тарифы/контакты/оформление и добавляет данные релиза из
`test-release-4.2.json`. Сначала загружает IPA, затем публикует конфигурацию.
Новое окно и баннер видны для сборок 400–419. Сборка 420 их уже не показывает.
При повторной публикации той же или более старой версии скрипт остановится.
Обычный Publish-Release.cmd остаётся для последующих выпусков.

Перед повторным запуском Publish-Config.cmd убедитесь, что используете папку
с конфигурацией, созданной после загрузки IPA, а не чистую копию из архива.

# Онлайн-настройки Apple Store 4.0

Публичный файл: `apple-store/configuration.json` в существующем R2 bucket `appleipa-files`.
Каталог `apple-store/catalog.json` остаётся отдельным и не перезаписывается.
Встроенная копия используется до первой успешной загрузки; последняя проверенная
онлайн-копия сохраняется на устройстве. Проверка при запуске/возвращении — не чаще
раза в 5 минут, ручная проверка в настройках — сразу.

После установки 4.0 без новой IPA можно менять:

| Поле JSON | Что меняется |
|---|---|
| purchase.tariffs | Название, цена, гарантия, срок действия, описание, рекомендация и доступность тарифа |
| purchase.enabled | Доступность оформления покупки |
| purchase.recipient / message | Telegram-получатель и шаблон заказа: {title}, {price}, {guarantee}, {validity} |
| links | Поддержка, канал, ссылка с подробностями сертификатов |
| news | Баннеры и всплывающие новости, текст, кнопка и её действие |
| changelog | Версии и короткие списки изменений |
| help / about | Инструкции, FAQ, сведения о приложении |
| labels | Подписи предусмотренных элементов: ключи перечислены в файле |
| layout.settings / home / tabs | Порядок и видимость предусмотренных блоков |
| appearance | Цвета светлой/тёмной темы, логотип внутри приложения, фон и изображение баннера |
| defaults | Начальные тема, автоочистка, фильтр доступности, без перезаписи выбора пользователя |
| features | Доступность Bundle ID, запросов, самообновления, переключателя темы и настройки автоочистки |
| update | Новая IPA, версия, номер сборки, размер, SHA-256, требования iOS и изменения |

Не меняются онлайн: исполняемый код, новые экраны/функции, иконка на рабочем столе,
Bundle ID, системные разрешения и алгоритмы подписи. Эти изменения требуют новой IPA.
Служебные параметры установки/подписи и лицензии по-прежнему скрыты в интерфейсе;
исходники и лицензии сохраняются отдельным артефактом сборки.

## Обычное изменение текстов/цен

1. Если файл на ПК старый, запустите Get-Config.cmd. Он сохранит текущую локальную копию в .bak.
2. Измените configuration.json в VS Code. Не помещайте в него пароли или сертификаты.
3. Увеличьте revision на 1. Сохраняйте стандартный JSON без комментариев.
4. Запустите Publish-Config.cmd.
5. Откройте настройки Apple Store и потяните вниз. Неверная конфигурация не заменит сохранённую.

Нельзя убрать вкладки catalog/settings и пункт certificate, чтобы пользователь
не потерял доступ к каталогу и сертификату. Отсутствие другого ключа layout скрывает блок.
Допустимые home: heading, search, news, featured, categories.
Допустимые tabs: catalog, library, settings.
Допустимые settings: certificate, theme, cleanup, update, support, channel, purchase,
catalog, request, help, about.

## Новость при входе

Добавьте объект в news (каждой новой новости — новый id):

```json
{
  "id": "update-4-1",
  "enabled": true,
  "title": "Доступно обновление Apple Store",
  "text": "Добавили новые возможности. Обновите приложение в настройках.",
  "button": "Обновление",
  "action": "update",
  "url": null,
  "modal": true,
  "minBuild": 400,
  "maxBuild": 400,
  "startsAt": null,
  "endsAt": null
}
```

modal показывает окно один раз для данного id на устройстве; новость остаётся в
блоке каталога. Действия: update, certificates, link, none. Для ссылки на разработчика:
`"action":"link", "url":"https://t.me/ellai95", "button":"Написать разработчику"`.
minBuild/maxBuild ограничивают версии получателей. Для отсутствия верхней границы — null.
Даты необязательны, пример `2026-10-08T12:00:00Z`. Это окно внутри приложения, не рассылка.

## Публикация новой IPA

Пока нет готовой проверенной IPA, update.enabled оставьте false.
GitHub выдаёт IPA и release.json с фактическими метаданными и SHA-256.
Publish-Release.cmd загружает IPA в путь `apple-store/releases/Apple-Store-ВЕРСИЯ-СБОРКА.ipa`
и после успешной загрузки публикует её данные в configuration.json. Новость автоматически
не включается: добавьте нужный текст в news сами или попросите подготовить его.
Если публикация конфигурации не удалась, повторите Publish-Config.cmd.
Не заменяйте файл по уже опубликованному пути версии: создавайте новый номер сборки.

Обновление 3.8 → 4.0 первый раз выполняется привычной внешней подписью.
Дальше механизм из настроек подписывает IPA на iPhone выбранным сертификатом,
сохраняя имя/Bundle ID. Для проверки обновления поверх потребуется последующая сборка
с большим номером. Системное подтверждение обязательно; совместимость сертификата
и завершение установки проверяет iOS. Не закрывайте Apple Store во время передачи.

Если новая онлайн-конфигурация сломала оформление, загрузите исправленную копию
с revision больше предыдущего. Интернет должен быть доступен на устройстве.
